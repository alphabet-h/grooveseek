# 8. 1.0.0 が何を凍らせるかを宣言し、Rust API はそこから外す

- Status: accepted
- Date: 2026-08-17
- Deciders: project owner
- Applies to: v1.0.0

## 背景と課題

semver は「public API を壊すなら major が要る」と言うが、**public API が何かは
言わない**。ライブラリなら問い自体が答えになる — crate が export しているものが
API である。しかしコマンドラインと MCP 面と HTTP transport と設定形式を持ち、
ユーザのホームディレクトリにファイルを書くプログラムでは、答えは「メンテナが
そう言ったもの」でしかない。そしてメンテナが何も言わなければ、利用者は当然
**観測できるものすべて**だと解釈する。

本決定の日に実測した値:

| | |
|---|---|
| public な Rust アイテム | **408 個**（24 個の `pub mod` にまたがる） |
| コマンドラインのフラグ | **138 個**（10 サブコマンド） |
| MCP tool / prompt | 6 / 4、加えて `kb://` resource スキーム |
| HTTP route | 5 |
| 設定セクション | 11、`deny_unknown_fields` が 25 箇所 |
| ディスク上の成果物 | 索引 DB / 設定 / 除外ファイル / eval セットと履歴 / サービス登録 |

これを全部 2.0.0 まで凍らせると、失敗の仕方が 2 つに 1 つになる。**誰も依存して
いない部分を永久に改善できない**か、**誰も気付かない変更のたびに major を出す**か
である。どちらも「どこが約束なのかを事前に書き下す」より悪い。

これを理屈でなく具体にしている項目が 1 つある。`/ui` の web 画面は自分の HTML で
自分を placeholder と名乗っており、作り直す予定になっている。宣言なしで 1.0.0 を
出せば、**その作り直しが 2.0.0 になる**。

## 判断基準

- 約束は、口にした瞬間に気前よく聞こえるものではなく、**1.x 全期間にわたって
  守れるもの**でなければならない
- 利用者は見ただけでは契約と実装詳細を区別できない。**書かれていないものは
  推測され、その推測は広い方に振れる**
- **Rust API は今日の時点で契約になっていない。これは主張ではなく実測である**:
  `cargo package -p grooveseek` は *"dependency `groove-tray` does not specify a
  version"* で失敗する（workspace が version 指定の無い path 依存を使っているため）。
  crates.io 上でこの 408 個に依存できるものは存在しないので、**1.0.0 を打っても
  凍らない** — 凍らせたくても凍らない
- 設定についての約束は**失敗の向きを選ぶ**ことである。理解できないキーを黙って
  無視するのも、大声で起動を拒むのも、どちらも弁護できるが、**どちらも安全では
  ない**

## 検討した選択肢

- **何も言わずに 1.0.0 を打つ。** 既定の解釈は「全部凍った」。守れないうえ、
  予定している `/ui` 刷新が major になるので却下
- **全部凍らせて、本当にそう扱う。** 誠実ではあるが、内部の refactor がすべて
  互換性の問題に化け、**1.0.0 が可能にするはずの作業を塞ぐ**
- **狭い面を書き下して宣言する。** 採用
- **面が全部凍らせられる大きさになるまで 1.0.0 を延期する。** 慎重に見えて
  そうでない選択肢。**面は放っておいても縮まない**し、0.x に居続けることは
  「約束を一度もしない」という別のやり方でしかない

## 決定

**安定な面を [docs/stability.ja.md](../stability.ja.md) に書き下す**（推測に委ねない）。
要約すると、コマンドライン / 機械可読な JSON / MCP の面 / `/mcp` と `/healthz` /
設定のキーと既定値 / 既定の embedding モデル / ユーザのファイルシステムに書かれる
名前。明示的に対象外なのは、管理用の web 面 / 人間向けの text 出力すべて /
DB の内部スキーマ / ログの文面 / Rust API。

このうち 3 点は、ポリシー側ではなくここに理由を置く。

**Rust API を外し、`grooveseek` に `publish = false` を付ける。** 文書化するだけで
なくマークするのは、意図を**強制可能**にするためである — `cargo publish` が拒否
するので、除外が事故で覆らない。これは問いを避けているのではない。**crate は今日
実際に package できない**ので、この除外は現実の記述である。将来の公開は独立した
判断であり、それ自身の安定性宣言を伴う。

**管理用の web 面は非安定。** `/ui` / `/api/search` / `/api/admin/status` は
GrooveSeek が認証を持たないため**仕様として loopback 限定**である。これらが相手に
しているのは自分のデータを見る運用者であって、統合する開発者ではない。
**非安定と宣言することが、予定している刷新を minor に留める唯一の方法である。**

**設定に前方互換性は無く、未知キーはエラーのまま。** 代案（警告して続行）は、
**大きな失敗を小さな失敗と交換する**。`model` の打ち間違いは、誰も読まない daemon の
stderr を警告 1 行が流れていく間に、**既定モデルでナレッジベースを索引させてしまう**。
設定ファイルはそれを読むバイナリの版に属する。ポリシーはそう書く — そうでないふりを
しない。

### 影響

- **他の 1.0 blocker が 3 つ、コードではなく本文書で解決する**: 既定 embedding
  モデルを契約の一部と宣言し、未知キー方針を確定し、サービス成果物名を凍結対象と
  名指しした。残るのは CLI と MCP の名前を寄せること、HTTP の `Origin` 既定を
  決めること、`search` レスポンスを全フィールド書き下すことの 3 つ
- **web 画面の作り直しは minor のままでいられる。** それが狙いだった
- **設定変更をまたぐダウングレードは大声で失敗する。** 1.0.x のバイナリは 1.1 の
  設定を拒む。これは打ち間違いを捕まえるために受け入れたコストである
- **`cargo package` は今も失敗するが、それは見落としではなく意図になった。**
  もし将来この失敗を直すなら、それは**公開すると決めたから**であるべきで、
  ついでの掃除としてやってはいけない
- **これがやっていないこと**: 面を小さくしてはいない。408 個の public アイテムは
  そのまま残っており、ソースを読む人にはどれが荷重を受けているか分からない。
  約束に合わせてコードを絞るのは別の作業であり、**本文書はその前提条件であって
  代替ではない**
